# ZOJ Editor Frontend

`editor.zoj.kr`의 독립 문제 제작 UI입니다. React·TypeScript·Vite를 사용하고,
ZOJ의 인디고 색상과 카드/폼/표 스타일에 맞춰 구성했습니다.

백엔드: https://github.com/ZERONE-Online-Judge/editor-backend-v1

## 개발

```sh
npm ci
npm run dev
```

http://127.0.0.1:5190 에서 열립니다. `/api` 요청은 `VITE_API_PROXY` 또는
기본 http://127.0.0.1:8011 로 프록시합니다. ZOJ 전송은 Editor 서버를 통해
권한을 확인하므로 브라우저에 연동 키나 ZOJ 로그인 토큰을 넣지 않습니다.
백엔드의 `deploy/dev.sh`로 API·워커·프런트엔드를 함께 실행할 수 있습니다.
ZOJ와 이메일·비밀번호·패스키·로그인 세션을 공유합니다. 운영 로그인과 계정 보안 관리는 ZOJ 공통 화면에서 인증한 뒤 원래 에디터 작업으로 복귀합니다. 독립 개발 모드의 인증번호는 백엔드의
`data/preview/development-mail`에 저장됩니다.

## 화면

- 이메일 우선의 ZOJ 공통 로그인·패스키·새 환경 추가 인증·세션 이동과 내 정보의 패스키 관리
- 내 문제/공유 문제 목록, 개인 폴더·하위 폴더·일괄 이동·끌어 놓기
- ZIP 가져오기, 새 문제, 휴지통 복원
- 문제 작업 공간: 지문, 파일, checker, validator, interactor, 테스트, 풀이
- 실제 검증 결과: 기대 판정 비교, 사례별 입출력과 CPU/메모리, 실행 기록
- 스트레스 테스트: 유효한 반례 찾기와 테스트 등록
- 공유 리비전, 변경 비교, 명시적 충돌 해결, 협업 권한과 이슈
- 공개 자료, Editor 또는 ZOJ 형식의 검증된 패키지 다운로드
- 같은 이메일의 ZOJ 대회 권한 조회·직접 등록·서버에 보관한 전송 기록
- 팀 폴더 구성원·대기 초대의 기능별 권한 편집 모달
- 모바일 메뉴, 저장하지 않은 변경 이탈 확인, 수식 미리보기

화면의 실행 결과는 서버에서 가져옵니다. 시뮬레이션 판정을 보여주지
않습니다. 생성·컴파일·채점·검증은 ZOJ 에이전트에서 실행합니다.

**테스트 · 생성 스크립트 → 전체 테스트 검사**에서 현재 세트 또는 모든
테스트 세트의 입력을 검사합니다. 등록 입력과 스크립트로 생성한 입력을
Validator로 확인하며 Main 풀이와 정답 생성은 필요하지 않습니다. 실행
결과에서 입력을 미리 볼 수 있고, 검사 결과는 자동으로 사본에 반영하지
않습니다. 생성 스크립트 문법, 입력 형식·중복 검사는 기존 규칙을 따릅니다.

생성·검증·자체 테스트·스트레스·렌더링·패키지 작업을 요청하면 접수 중
표시와 함께 중복 요청을 막고, 접수 직후 **실행 결과** 탭에서 해당 작업을
자동으로 엽니다. 접수 실패 시에는 현재 화면에 오류를 표시합니다.

**전체 검증** 탭에서 풀이 검증 환경·풀이·테스트 범위를 선택해 실행합니다.
전체 검증·스트레스 테스트·패키지 탭은 실행 설정과 요청만 담당합니다.
기록과 결과는 **실행 결과** 탭에서만 확인합니다. 각 실행 화면의 기록
바로가기는 해당 작업 유형을 선택한 실행 결과를 열며 작업을 요청하지 않습니다.

검증 테스트 세트는 기본적으로 현재 세트 하나를 사용합니다. **전체 세트**를
선택하면 모든 세트의 테스트를 한 작업에서 검증하고 세트별 진행률을 표시합니다.
테스트 번호와 그룹, 기대 판정은 세트별로 유지합니다. 번호 범위와 개별 테스트
선택은 한 세트에서만 지원합니다. 빈 세트나 NR 범위는 실행 대상으로 세지 않습니다.

**실행 결과**에서 입력·정답 생성, 입력 생성·검사, 저장 입력 검사, 정답 생성,
풀이 검증·전체 검증, Validator 검사, Checker 검사, 스트레스 테스트,
지문 파일 생성, 패키지 생성을 각각 필터링합니다. 서버에서 유형별 총개수와
페이지를 계산하며, 유형을 바꾸면 첫 페이지의 해당 유형 결과를 선택합니다.
기록 제목과 상세 제목·설명은 같은 기준을 사용하고, 별도 지정한 이름은
‘요청 이름’으로 보존합니다. 실행 요청이 접수되면 해당 결과로 바로 이동합니다.

기록 주소에 작업 ID를 보관해 링크 공유와 뒤로 가기를 지원합니다. 예전
`verification?job=...`, `stress?job=...`, `packages?job=...` 주소도 실행 결과로
이동하며 작업을 다시 요청하지 않습니다. 결과를 불러오는 동안 이전 기록의
결과·반영 버튼은 표시하지 않습니다.

문제 패키지를 가져오면 바로 작업 공간으로 이동하지 않고, 복원된 지문·풀이·
테스트·파일 수와 변환 확인 사항을 먼저 표시합니다. Polygon의 스트레스 설정,
원본 지문 파일 등은 실행에 자동 첨부하지 않는 보조 파일로 보관하며 대응표를
펼쳐 확인할 수 있습니다. `문제 열기`로 작업을 계속하거나 목록으로 돌아갑니다.

## 동료의 새 커밋 안내

문제 작업 공간을 열어 두면 동료의 커밋을 감지하여 화면 위에 안내합니다.
작성 중인 내용은 자동으로 바꾸지 않습니다. `업데이트`를 누르면 현재
작업을 저장한 뒤 최신 공유 리비전과 병합하며, 같은 항목을 수정했다면
기존 충돌 해결 화면을 이용합니다. 읽기 전용 사용자는 최신 공유 문서를
불러옵니다. 안내를 닫아도 상단의 `업데이트 가능` 표시가 남고, 다음
커밋이 도착하면 새 안내를 표시합니다.

감지는 인증된 `/revision-status` 요청으로 수행합니다. 숨겨진 탭은 요청을
중단하고 다시 보이거나 연결이 복구되면 재개합니다. 배포 시 백엔드를
먼저 반영해야 합니다. DB 변경이나 별도 메시지 서버는 필요하지 않습니다.

## 별도 서버 배포

Dockerfile과 `deploy/nginx.conf.template`을 제공합니다. 백엔드 저장소의
`deploy/compose.yaml`에서 프런트엔드와 API를 함께 실행합니다.
호스트 포트·SMTP·TLS·DB 설정은 백엔드 배포 문서를 따릅니다.
`VITE_API_PROXY`는 개발용이며 운영은 동일 도메인의 `/api`를 사용합니다.

## 브랜치

각 기능 브랜치는 앞 브랜치를 기반으로 쌓았습니다.
`integration/editor-v1`에 전체 구현이 있습니다. 운영 `main` 푸시는 빌드와
테스트를 통과한 뒤 전용 Editor 러너에서 배포합니다. 기능 브랜치와 PR은
GitHub 호스팅 러너에서 검증하며 운영 서버에서 실행하지 않습니다.

- `feature/interface-foundation`: 독립 도구·디자인 토큰·공통 UI
- `feature/email-login`: 인증번호 로그인·프로필·서비스 탐색
- `feature/problem-workspace`: 목록·편집·작업 사본·협업·충돌 해결
- `feature/verification-interface`: 실행 기록·반례·패키지 UI
- `feature/service-deployment`: 별도 서버 이미지·CI·문서

커밋 메시지는 `AGENTS.md`에 지정된 모든 규칙을 따릅니다.
Polygon 공개 명세의 대응 범위와 차이는 백엔드의
`docs/polygon-reference.md`에 기록했습니다.

- `feature/project-folders`: 개인 폴더·하위 폴더·선택 이동 UI
- `feature/zoj-publishing`: ZOJ 패키지·대회 등록·전송 기록 UI
- `feature/self-hosted-deployment`: 전용 서버 러너·검증 후 자동 배포

- `feature/shared-login`: ZOJ 공통 로그인과 내 정보 비밀번호 설정
- `feature/execution-navigation`: 요청 작업 바로 보기·기록과 새 실행 분리

### 공유 작업 폴더

문제 목록의 **공유 작업 폴더 +**에서 공동 작업 공간을 만듭니다.
공유 폴더를 선택하고 **구성원**을 열어 이메일로 초대하세요. 상대방은
로그인 후 **받은 초대**에서 수락합니다. 이메일은 발송하지 않습니다.

관리자·편집자·검수자·번역자·읽기를 선택할 수 있습니다. 권한은 하위
폴더와 기존·신규 문제에 모두 적용됩니다. 구성원 화면에서 권한을
변경하거나 초대를 취소하고, 내보내기 또는 탈퇴할 수 있습니다.

개인 폴더 정리는 자신에게만, 공유 폴더 정리는 구성원 모두에게 적용됩니다.
문제를 공유 영역으로 옮기거나 다른 공유 영역으로 옮길 때에는 원래 문제
소유자의 공유 범위 확인이 필요합니다. 문제별 직접 공유는 폴더 초대와
별도로 유지됩니다. 문제 삭제·ZOJ 배포는 원래 문제 소유자만 가능합니다.
